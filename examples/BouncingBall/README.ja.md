# BouncingBall

> English: [README.md](README.md)

状態を描画の外で更新してBallを動かすサンプルです。

## 準備と実行

1. [サンプル入門ガイド](../../docs/GUIDE_EXAMPLES.ja.md)で導入条件と必要な機器を確認します。対応するボード・外部ライブラリはルートREADMEを参照します。
2. [BouncingBall.ino](BouncingBall.ino)を開き、実際のボードとポートを選びます。次のincludeで使う依存機能も準備してください。

   `<M5Unified.h>`, `<LGFXVirtualCanvas.h>`

3. 書き込み後は画面／入力など、この例の出力先で確認します。シリアルを使う場合はソースの初期化条件に合わせます。

## 動作の流れ

状態を描画の外で更新してBallを動かす例です。詳細なAPIとデータの扱いは次の項目で確認します。

以下はソース内で最初に現れるAPIの順です。コールバック登録の位置は、実際の呼び出し順序とは異なります。

1. `screen.setMemoryLimit(...)` — 確保前に作業バッファの予算を決め、収まらない場合にも対応します。
2. `screen.begin(...)` — 前提となる機器を準備してから初期化し、結果を返すAPIでは成否を確認します。
3. `screen.render(...)` — 同じ状態のSceneを描きます。タイル描画ではコールバックが複数回呼ばれます。

## APIの使い方と注意点

実パネルを初期化してから仮想Screen／Spriteの領域を確保します。描画コールバックはタイルごとに複数回呼ばれ得るため、同じ状態を描く処理にし、その中でアニメーション更新・入力消費・1回限りの入出力を行いません。状態は外で更新してからrenderします。

Screenは仮想画面全体、Spriteは表示領域内のローカル座標です。メモリ上限はタイル領域の制限で、アプリ全体の確保量ではありません。begin／renderの結果やPSRAM診断を確認し、要求したメモリ種別を思い込みません。

差分モードが減らすのは転送で、コールバックの実行ではありません。パネルへ直接描いたら比較情報をinvalidateします。透過描画は対象外の画素を残す処理で、閉じた際の背景復元は別途必要です。

## 確認と問題の切り分け

状態を描画の外で更新してBallを動かすことを出力から確認します。まず例のままの入力で試し、その後に設定やデータ源を1つずつ変えます。

| 症状 | 最初に確認すること |
|---|---|
| 出力がない | ボード／依存ライブラリ、初期化結果、表示先とシリアル速度 |
| 開始するが途中で止まる | 待機条件、バッファの空き、相手や入力の準備、継続呼び出し |
| 値が不自然・不安定 | 長さと単位、形式、寿命、共有状態、部分的な処理結果 |

共通の考え方は[入門ガイド](../../docs/GUIDE_EXAMPLES.ja.md)、別の例は[サンプル一覧](../README.ja.md)へ進んでください。
